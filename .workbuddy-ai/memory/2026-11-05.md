## 温度条由横向改为纵向共用刻度

- 用户提问「这个温度条是不是竖着展示更加直观一些」，附 GPU 卡片截图。
- 结论：是。原横条各自按自己的停机线归一化（45/85=53%、47/100=47%、64/96=67%），长度相近却代表不同绝对温度，横向比较失真。
- 实现（`SystemTemperaturePage.tsx` + `styles.css`，未提交）：
  - 新增 `TEMP_SCALE_TOP = 110` 与 `scalePercent()`；替换 `CHART_Y_MIN`、移除 `meterPercent` 引用。实时柱状读数与历史曲线共用 0–110°C 刻度顶。
  - 柱高 = 绝对温度 / 110；虚线 = 各自停机线；柱顶到虚线的空白 = 余量；暖色带只覆盖 `WARM_MARGIN_C`（8°C）到停机线，越线后不再着色。
  - 虚线颜色跟随传感器色，与历史曲线一致；越线时改白，避免与 danger 红填充同色而消失。
  - `role="meter"` 的 `aria-valuemax` 从「各自 limit」改为 110 以匹配视觉刻度；`aria-valuetext` 补充共用刻度、停机线与余量。
  - 加一行 `.temps-scale-note` 说明编码：「三条共用 0–110°C 刻度 · 虚线是各自停机线，柱顶到虚线就是余量」。
  - 移动端三柱保持并排（88px 高）而非逐行堆叠，GPU 卡高度 541→497px，整页 3357→3258px；CPU 卡仍走两列紧凑布局。
- 验证：tsc / build / web 173 单测 / 16 项令牌漂移 / `git diff --check` 全通过；桌面与移动端 axe 0 violations、无横向溢出、无 console 错误；正常、超限、缺失、单卡状态均检查过。
- 注意：实时 Prometheus 上游 `192.168.1.102:9090` 仍不可达，截图用 mock 数据生成。
